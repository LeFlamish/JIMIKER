# 플레이 콘솔 등록 → 출시 실행 순서

`play-store.md`가 "준비물 목록"이라면 이 문서는 "콘솔에서 실제로 누르는 순서"다.
위에서부터 차례로 하면 된다. 준비물의 세부(키스토어 만들기, 데이터 안전 답안 표,
설명 초안)는 `play-store.md`를 참조한다.

---

## 0단계. 올리기 전에 로컬에서 끝낼 것

1. **서버 배포** — 함수 없이 올리면 예약·검색이 안 되는 앱이 심사받는다.
   ```bash
   firebase functions:secrets:set PLACES_API_KEY   # 최초 1회
   firebase deploy --only functions,firestore:rules
   ```
2. **테스트 데이터 정리** — Firestore의 연습용 창고·예약을 지운다.
   (storages / locations / zones / reservations / usages / endeds / chat_rooms)
3. **앱 아이콘** — 지금은 Flutter 기본 로고다. 512×512 PNG를 만들어
   `flutter_launcher_icons`로 적용한다. (스토어 등록정보에도 같은 파일 사용)
4. **업로드 키스토어 + key.properties** — `play-store.md` 1번 절차 그대로.
5. **AAB 빌드와 서명 확인**
   ```powershell
   flutter build appbundle
   # 소유자에 내 이름이 나와야 한다. CN=Android Debug면 key.properties를 못 읽은 것.
   & "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" `
     -list -printcert -jarfile build\app\outputs\bundle\release\app-release.aab
   ```
6. **릴리스 APK로 폰 테스트** — `flutter build apk --release` 설치 후
   로그인·지도·검색·예약·채팅 한 바퀴.

## 1단계. 개발자 계정 등록

https://play.google.com/console/signup

- **개인 / 조직** 중 **개인** 선택. (조직은 사업자등록 + D-U-N-S 번호가 필요)
- **등록비 $25** — 일회성, 해외 결제 되는 카드.
- **신원 확인** — 신분증(주민등록증·운전면허·여권) 업로드. 승인까지 며칠 걸릴 수 있다.
- 개발자 이름(스토어에 표시됨), 연락처 이메일·전화 인증.
- 구글 계정에 **2단계 인증**을 켜야 한다 (필수).

### ⚠️ 개인 계정의 테스트 요건 — 미리 알아야 할 가장 큰 변수

새로 만든 개인 개발자 계정은 **프로덕션(정식 출시) 신청 전에 비공개 테스트를
일정 인원이 14일 연속 참여한 상태로 유지**해야 한다. 인원 기준은 현재 12명
(예전 20명에서 완화됨) — 콘솔 화면에 표시되는 숫자가 최종 기준이다.

→ **지인 12명 이상의 구글 계정 이메일을 지금부터 모아두자.**
테스터는 링크 한 번 누르고 앱을 설치만 하면 되지만, 14일 동안
참여 상태를 유지해야 하므로 중간에 나가지 말라고 부탁해둔다.

## 2단계. 앱 만들기

콘솔 → 모든 앱 → **앱 만들기**

| 항목 | 값 |
|---|---|
| 앱 이름 | 지미커 |
| 기본 언어 | 한국어(대한민국) |
| 앱 또는 게임 | 앱 |
| 유료/무료 | **무료** (한 번 무료로 게시하면 유료 전환 불가 — 우리는 무료라 무관) |

선언 체크 2개(개발자 프로그램 정책, 미국 수출 법규) 동의 → 만들기.

## 3단계. 대시보드 "앱 설정" 설문 채우기

앱 대시보드에 "설정 절차" 체크리스트가 뜬다. 순서대로:

| 설문 | 답 |
|---|---|
| 앱 액세스 권한 | "모든 기능이 특별한 액세스 권한 없이 사용 가능" — 구글 계정만 있으면 즉시 가입되므로. 메모란에 "Google 계정으로 즉시 가입 가능"이라고 적어주면 심사가 부드럽다 |
| 광고 | 광고 없음 |
| 콘텐츠 등급 | 설문 시작 → 이메일 입력 → 카테고리 "기타 앱 유형(유틸리티 등)" → 폭력·성적 콘텐츠·비속어·약물·도박 전부 아니오 → **사용자 간 상호작용(채팅·콘텐츠 공유): 예** → 사용자 위치 공유: 아니오(지도는 매물 위치이지 내 위치 공유가 아님) → 전체이용가 등급이 나온다 |
| 타겟층 | **만 18세 이상** (거래 서비스) |
| 뉴스 앱 | 아니오 |
| 데이터 보안 | `play-store.md` 3번 표를 **그대로** 입력. 암호화 예, 삭제 요청 예. "기기 또는 기타 ID"를 빠뜨리면 AD_ID 불일치로 반려된다 |
| 정부 앱 | 아니오 |
| 금융 기능 | 없음 (앱 안에서 결제·송금하지 않는다) |
| 개인정보처리방침 | https://yeoby97.github.io/JIMIKER-legal/privacy.html |
| 계정 삭제 | 데이터 보안 안의 계정 삭제 URL: https://yeoby97.github.io/JIMIKER-legal/account-deletion.html |
| 앱 카테고리 | 앱 → 라이프스타일 (비즈니스도 무방) |
| 스토어 연락처 | 이메일 필수 (문의 주소와 동일하게) |

위치 권한은 전면(포그라운드)만 쓰므로 별도의 민감 권한 선언 양식은 뜨지 않는다.
(백그라운드 위치·SMS·통화기록을 쓰지 않는다)

## 4단계. 스토어 등록정보

성장(Grow) → 스토어 등록정보 → 기본 스토어 등록정보

- 앱 이름: 지미커
- 짧은 설명(30자)·자세한 설명(4000자): `play-store.md` 4번 초안 복사
- 앱 아이콘: **512×512 PNG**
- 그래픽 이미지(피처 그래픽): **1024×500** PNG/JPG
- 휴대전화 스크린샷: **최소 2장** (1080×1920 세로 권장, 최대 8장)
  — 실기기에서 지도·바텀시트·예약·채팅 화면을 캡처하면 된다
- 저장

## 5단계. 비공개 테스트에 AAB 업로드

테스트 및 출시 → 테스트 → **비공개 테스트** → 트랙(기본 제공되는 트랙 사용) →

1. **테스터 탭**: 이메일 목록 만들기 → 지인 12명+의 구글 계정 이메일 등록 → 저장.
2. **새 릴리스 만들기**:
   - 처음이면 "Play 앱 서명" 동의가 뜬다 → **기본값(구글 생성 키) 그대로 계속**.
   - `build\app\outputs\bundle\release\app-release.aab` 업로드.
   - 릴리스 이름은 자동(1 (1.0.0)), 출시 노트에 "첫 테스트 버전입니다" 정도.
3. 다음 → 저장 → **검토 후 출시**. 국가는 **대한민국** 추가.
4. 테스터 탭의 **웹 참여 링크**를 복사해 테스터들에게 보낸다.
   테스터: 링크 열기 → 수락 → 플레이스토어에서 지미커 설치.
5. 첫 릴리스는 심사를 거친다(수 시간~며칠). "검토 중"이 정상이다.

⚠️ **다음 업로드부터는 versionCode를 올려야 한다.**
`pubspec.yaml`의 `version: 1.0.0+1`에서 `+` 뒤 숫자를 1씩 증가(1.0.0+2, +3…).
같은 번호는 업로드가 거부된다.

---

## 6단계. 업로드 직후 — Play 서명 SHA-1 등록 (가장 많이 빼먹는 단계)

구글이 AAB를 받아 **자기 키로 다시 서명**하므로, 그 키의 지문을 등록해야
스토어에서 받은 앱에서 구글 로그인과 지도가 동작한다.

1. 콘솔 → 테스트 및 출시 → 설정 → **앱 무결성(App integrity)** →
   "앱 서명 키 인증서"의 **SHA-1** 복사.
2. **Firebase 콘솔** → 프로젝트 설정 → `com.jimiker2.app` 앱 → 디지털 지문 추가.
   (google-services.json은 다시 받지 않아도 된다)
3. **Google Cloud 콘솔** → Maps 키의 Android 제한에도 같은 SHA-1 + 패키지명 추가.

안 하면 증상: 내가 빌드한 APK는 되는데 **스토어에서 받은 앱만** 로그인 실패/지도 회색.

---

## 7단계. 14일 테스트 → 프로덕션 출시

1. 테스터 12명+가 14일 **연속** 참여 상태를 유지한다.
2. 조건이 차면 대시보드에 **"프로덕션 이용 권한 신청"** 이 활성화된다 →
   설문(테스트에서 무엇을 확인했나, 대상 사용자는 누구인가 등)에 성실히 답변.
3. 승인되면: 프로덕션 → 새 릴리스 만들기 → AAB 업로드(테스트에서 쓴 버전
   재사용 가능) → 국가 선택 → 검토 후 출시.
4. 심사 통과(보통 2~7일, 첫 앱은 더 걸릴 수 있음) 후 스토어에 게시된다.
   검색 노출은 게시 후에도 시간이 좀 걸린다.

## 자주 막히는 곳

- **신원 확인 지연** — 계정 등록을 제일 먼저 해두고 나머지를 병행하는 게 낫다.
- **versionCode 중복** — pubspec의 `+N`을 안 올리고 다시 빌드한 경우.
- **데이터 안전 불일치 반려** — "기기 또는 기타 ID"(AD_ID) 누락이 단골.
- **개인정보처리방침 404** — 시크릿 창에서 URL 열리는지 확인 (`play-store.md` 2번 체크).
- **스토어 버전만 로그인 실패** — 6단계(Play 서명 SHA-1)를 빼먹은 것.
- **심사자가 로그인을 못 해 반려** — 앱 액세스 권한에 "구글 계정으로 즉시
  가입 가능"을 적어두면 예방된다.
